## มันทำอะไร

- **ถามเมื่อคำสั่งไม่ชัด** ถ้าคำขออย่าง "ทำให้ดีขึ้น" ตีความได้หลายแบบ มันจะบอกความหมายที่น่าจะเป็น บอกว่ามันจะเลือกแบบไหน แล้วรอคุณตอบก่อนลงมือ
- **วางแผนก่อนสร้าง** ฟีเจอร์ใหม่จะได้แผนสั้น ๆ กับรายการงานก่อน ถ้าคุณขอมาแค่ประโยคเดียว มันจะถามไม่กี่ข้อ แต่ละข้อมีคำตอบตั้งต้นให้ตอบ "ok" ได้
- **เก็บแผนไว้ในไฟล์** `docs/STATE.md` เก็บว่ากำลังทำอะไร ต่อไปทำอะไร และข้ามอะไรไป เซสชันใหม่อ่านไฟล์นี้ คำสั่ง "ทำที่เหลือให้เสร็จ" ในวันถัดไปจึงใช้ได้
- **รันการตรวจของโปรเจกต์หลังแก้ทุกครั้ง** คุณอนุมัติคำสั่งครั้งเดียวบนเครื่องของคุณ และอนุมัติใหม่เมื่อคำสั่งเปลี่ยน โปรเจกต์ของคนอื่นจึงรันคำสั่งที่คุณยังไม่เห็นไม่ได้ ถ้าไม่ผ่าน Claude ต้องแก้ก่อนจะบอกว่า "เสร็จ" ได้ ถ้าเป็นเว็บไซต์ มันจะให้ Claude เปิดดูหน้าเว็บด้วย
- **แนะนำไลบรารีฟรี** ก่อนจะเขียนปฏิทิน แผนที่ หรือกราฟเอง
- **กันคำสั่งที่ทำลายงานไว้บางคำสั่ง** เช่น force push และการอ่าน `.env`
- **หยุดการ commit ที่จะบันทึก API key หรือรหัสผ่าน** และบอกว่าอยู่ในไฟล์ไหน เพราะ key ที่อยู่ในเวอร์ชันที่บันทึกแล้วจะค้างอยู่ในประวัติตลอดไป
- **ตอบเป็นภาษาของคุณ** และเปิดโหมดคำตอบสั้นภาษาง่ายได้ด้วยคำสั่งเดียว
- **แสดงความคืบหน้า และรวมทุกฟีเจอร์ไว้เป็นปุ่ม** แผงความคืบหน้าแสดงงานที่กำลังทำ ขั้นที่ทำอยู่ ("ขั้น 3 จาก 6: กำลังสร้างหน้า 2") และค่าใช้จ่ายของงานนี้กับของทั้งเซสชัน แผงควบคุมมีปุ่มสำหรับทุกฟีเจอร์ คือระดับ autoship โหมดประหยัด คำตอบภาษาง่าย skills และการตั้งค่าโปรเจกต์ แผงทั้งสองทำงานนอก Claude จึงไม่เพิ่มค่าใช้จ่ายของงาน มันใช้ฟีเจอร์ของ Claude Code ที่ยังอยู่ในช่วงทดลอง ถ้า Claude Code ของคุณยังไม่แสดงแผงของปลั๊กอิน ก็ไม่มีอะไรเปลี่ยน และเมื่อแสดงได้แล้ว `/easyclaude-panels` จะเปิดแผงขึ้นมา

แต่ละข้อไม่ใช่ของใหม่ ทุกข้อเป็นความสามารถปกติของ Claude Code คือไฟล์ hook หรือกฎสิทธิ์ easyClaude ตั้งค่าให้คุณ และวัดผลว่าผลลัพธ์ดีขึ้นจริงไหม

## เปิดแล้วอะไรเปลี่ยน

คำขอเดียวกัน ในร้านตัวอย่างเล็ก ๆ ร้านเดียวกัน รัน 3 รอบแบบมี easyClaude และ 3 รอบแบบไม่มี

| คุณพูดว่า | Claude Code ธรรมดา | เมื่อมี easyClaude |
|---|---|---|
| *"หน้าชำระเงินพังถ้าไม่ใส่โค้ดส่วนลด"* (ถามเป็นภาษาอังกฤษ) | แก้ได้ แต่ไม่เพิ่มเทสต์ที่จับบั๊กนี้ได้ถ้ามันกลับมาเลย 0 ใน 3 | แก้และเพิ่มเทสต์นั้น 3 ใน 3 |
| งานเดียวกัน ถามเป็นภาษาไทย | แก้ได้ และเพิ่มเทสต์นั้น 2 ใน 3 | มีเทสต์ 3 ใน 3 และตอบเป็นภาษาไทยตลอด |
| วันแรก: ห้าอย่าง *"วันนี้ทำแค่อย่างแรก"* วันที่สอง ในเซสชันใหม่: *"ทำที่เหลือให้เสร็จ"* | 0 ใน 3 เซสชันใหม่ไม่รู้ว่า "ที่เหลือ" คืออะไร | ทั้งห้าอย่างใช้ได้ 2 ใน 3 อีกรอบแยกค่าส่งไปไว้ในยอดรวมอีกตัว ที่หน้าชำระเงินไม่ได้ใช้ |
| *"อยากได้เวอร์ชันเมื่อวานคืน"* | ถามก่อนแก้อะไร 1 ใน 3 รอบที่เหลือกู้คืนทันที หรือส่งคำสั่ง git มาให้รันเอง | บอกว่าจะกู้อะไรคืน และถามก่อน 3 ใน 3 |
| *"อยากทำเว็บให้ร้านเบเกอรี่"* ในโฟลเดอร์ว่าง | เขียนแผนหรือทำหน้าเว็บเสร็จเลยโดยไม่ถาม 3 ใน 3 | ถามคำถามง่าย ๆ หนึ่งข้อก่อน 3 ใน 3 |
| *"เพิ่มปฏิทินให้ลูกค้าเลือกวันส่ง"* | ถามก่อน 2 ใน 3 อีกรอบเขียนปฏิทินเองทันที | บอกชื่อไลบรารีปฏิทินฟรี และถามก่อนเพิ่ม 3 ใน 3 |

**งานที่ไม่ต่างกัน** เพิ่มค่าส่ง *"ทำให้เทสต์ผ่าน"* โดยไม่แก้เทสต์ให้หละหลวม และเปลี่ยนชื่อร้านทั้งภาษาอังกฤษและภาษาไทย ทั้งสองแบบทำถูกทุกรอบ

**ค่าใช้จ่าย** งานที่มันช่วย มันทำงานมากกว่า จึงแพงกว่า: แก้บั๊กราว $0.23 เทียบกับ $0.13 และงานสองวัน $0.86 เทียบกับ $0.33 (Sonnet 5 ราคาเต็ม ถ้าใช้แพ็กเกจ Claude จะนับเป็นโควตาแทน) งานที่ไม่ต่างกัน ค่าใช้จ่ายพอ ๆ กัน และทุกเทิร์นมีการตั้งค่าของมันราว 1,700 โทเคน ถ้าคุณใช้ Claude แค่ถามคำถามหรือขอโค้ดทีละชิ้น อาจไม่คุ้ม

**วัดอย่างไร** สามแถวแรกวัดวันที่ 2-3 ตุลาคม 2026 บนรุ่น 0.2.6 แถวภาษาไทยวัดหลังแก้เรื่องภาษาในรุ่น 0.2.7 สามแถวแรก ตรวจไฟล์ที่ Claude ทิ้งไว้ด้วยเทสต์ที่ Claude มองไม่เห็น สามแถวหลัง Claude อีกตัวให้คะแนนคำตอบตามเกณฑ์ที่เขียนไว้ 3 รอบเป็นตัวอย่างที่น้อย ผลแต่ละแถวขยับได้หนึ่งรอบในแต่ละวัน รอบเหล่านี้ใช้คำสั่งในเครื่องไม่ได้ ซึ่งเข้าข้าง easyClaude เพราะการตรวจของมันรันเป็น hook รายละเอียดทุกรอบอยู่ใน [`evals/README.md`](evals/README.md)

## ติดตั้ง

ต้องมี **Claude Code** ([แอปเดสก์ท็อป](https://claude.ai/download) หรือในเทอร์มินัล) **[Node.js](https://nodejs.org)** (รุ่น LTS) และ **[Git](https://git-scm.com/downloads)** ไม่ต้องมีบัญชี GitHub

**วิธีที่ง่ายที่สุด: ให้ Claude ติดตั้งให้** เปิด Claude Code ในโฟลเดอร์ไหนก็ได้ แล้ววางข้อความนี้

```
ช่วยติดตั้งปลั๊กอิน easyClaude ของ Claude Code ให้หน่อย ก่อนอื่นตรวจว่ามี Node.js กับ Git
ไหม ถ้าขาดอะไรให้บอกวิธีติดตั้งเป็นภาษาง่าย ๆ จากนั้นรันสองคำสั่งนี้
claude plugin marketplace add kotaraa09/easyClaude
claude plugin install easyclaude@easyclaude
ถ้าไม่เจอคำสั่ง claude ให้บอกวิธีติดตั้ง Claude Code สำหรับเทอร์มินัล
เสร็จแล้วบอกให้ฉันเริ่มเซสชันใหม่
```

Claude จะขออนุญาตก่อนรันแต่ละคำสั่ง จากนั้นให้เริ่มเซสชันใหม่ ในแอปเดสก์ท็อปหรือในเทอร์มินัลก็ได้

<summary><b>ติดตั้งเอง</b></summary>

<br>

ในเทอร์มินัล ให้รันสองคำสั่งเดียวกัน

```bash
claude plugin marketplace add kotaraa09/easyClaude
claude plugin install easyclaude@easyclaude
```

ใน Claude Code ที่เปิดในเทอร์มินัล พิมพ์ `/plugin marketplace add kotaraa09/easyClaude` และ `/plugin install easyclaude@easyclaude` ก็ได้ ในแอปเดสก์ท็อป `/plugin` จะเปิดหน้าเลือกดูปลั๊กอินและไม่ได้ติดตั้งอะไร จึงต้องใช้คำสั่งด้านบน

[`template/`](template/) เป็นโปรเจกต์ไว้ fork ที่ชี้ไปที่ปลั๊กอินไว้แล้ว Claude Code ควรเสนอติดตั้งให้เมื่อคุณกดเชื่อถือโฟลเดอร์ แต่ในแอปเดสก์ท็อป ตอนทดสอบไม่มีหน้าเสนอขึ้นมา จึงต้องติดตั้งก่อน

## ครั้งแรกที่ใช้

เปิดโปรเจกต์แล้วบอกว่าอยากได้อะไร ถ้าโปรเจกต์ยังไม่ได้ตั้งค่า easyClaude จะถามไม่เกินสี่ข้อ คือคุณสร้างอะไร ใครใช้ และอะไรต้องทำงานได้ ที่เหลือมันดูเอาจากไฟล์ จากนั้นจะเขียนไฟล์ไม่กี่ไฟล์ลงใน `docs/` และเสนอสกิลเสริมที่เหมาะกับโปรเจกต์ไม่เกินสองตัว พร้อมบอกค่าใช้จ่ายของแต่ละตัว

หลังจากนั้น ทุกเซสชันจะเริ่มแบบนี้

```
ตอนนี้:     เพิ่มการรีเซ็ตรหัสผ่านในฟอร์มล็อกอิน
ถัดไป:      จำกัดจำนวนครั้งในการขอรีเซ็ต
ติดอยู่:     ไม่มี
ค้างไว้:     3 รายการ - โทเคนรีเซ็ตไม่มีวันหมดอายุ
```

บรรทัด "ค้างไว้" จะขึ้นเฉพาะเมื่อมีงานที่ตั้งใจข้ามไป<!--skill:kickoff-->

## แค่บอกว่าอยากได้อะไร

| คุณพูดว่า | สิ่งที่เกิดขึ้น |
|---|---|
| *"เพิ่มโปรไฟล์ผู้ใช้"* | มันเขียนแผนกับรายการงาน แล้วรอคุณตอบตกลง <!--skill:plan-feature--> |
| *"ทำต่อเลย"* | มันสร้างงานถัดไป แล้วตรวจ <!--skill:build-task--> |
| *"มันขึ้น error"* | มันหาสาเหตุ แก้ และเพิ่มเทสต์ <!--skill:debug--> |
| *"ship เลย"* | มันตรวจ รีวิว commit แล้วเปิด pull request <!--skill:ship--> |
| *"ระบบล็อกอินอยู่ตรงไหน"* | มันค้นก่อนจะอ่าน <!--skill:explore-code--> |
| *"อยากได้เวอร์ชันเมื่อวานคืน"* | มันหาว่าอะไรเปลี่ยน และถามก่อนจะคืนอะไร <!--skill:rescue--> |

การแก้เล็ก ๆ ข้ามขั้นตอนทั้งหมดนี้

<summary><b>คำสั่งต่าง ๆ</b></summary>

งานทั่วไปไม่ต้องใช้คำสั่งเหล่านี้เลย และมันไม่มีค่าใช้จ่ายจนกว่าคุณจะพิมพ์

```
/easyclaude:start              รันการตั้งค่าเอง

/easyclaude:security-check     หาความลับที่หลุดและความเสี่ยง ก่อนเปิดให้คนอื่นเห็น
/easyclaude:deploy             เอาขึ้นออนไลน์ แล้วตรวจที่อยู่เว็บจริง
/easyclaude:generate-asset     รูป เสียง และ 3D ผ่านผู้ให้บริการที่คุณมีคีย์
/easyclaude:pick-library       หาและตรวจไลบรารีก่อนจะเขียนเอง
/easyclaude:skills             เพิ่มสกิลจากที่อื่นที่เหมาะกับโปรเจกต์นี้
/easyclaude:connect            เชื่อมเครื่องมืออื่น (เบราว์เซอร์ Figma GitHub)
/easyclaude:cheap <งาน>        ทำงานหนึ่งอย่างด้วยขั้นตอนน้อยที่สุด
/easyclaude:cheap-session      อยู่ในโหมดประหยัดจนกว่าจะพิมพ์ /easyclaude:full
/easyclaude:full               ออกจากโหมดประหยัด
/easyclaude:plain [off]        คำตอบสั้นภาษาง่าย
/easyclaude:autoship pr        เลิกถามก่อน commit push และเปิด pull request (off, commit, push, pr, merge)
```

</details>

<details>
<summary><b>รูป เสียง และ 3D</b></summary>

<br>

Claude สร้างของพวกนี้เองไม่ได้ `/easyclaude:generate-asset` จึงส่งงานไปที่ผู้ให้บริการที่คุณมี API key คือ Replicate, ElevenLabs, OpenAI, Gemini หรือ Venice หรือ Automatic1111 และ ComfyUI บนเครื่องของคุณเอง มันถามก่อนใช้เงิน และบันทึกผลแต่ละครั้งไว้ใน `docs/asset-log.md` การสมัครแพ็กเกจอย่าง ChatGPT Plus ไม่ใช่ API key

ตอนนี้ทดสอบครบทุกขั้นแล้วแค่รูปจาก Replicate คำสั่ง `node scripts/gen/generate.mjs --list` บอกว่าผู้ให้บริการแต่ละรายสร้างอะไรได้จริงแล้วบ้าง

</details>

<details>
<summary><b>เชื่อมเครื่องมืออื่น</b></summary>

<br>

`/easyclaude:connect` เพิ่ม MCP server จากฟอร์มใน `.env` มีสามตัวที่ไม่ต้องใช้คีย์ คือ **playwright** (เบราว์เซอร์จริง) **inspo** (ตัวอย่างดีไซน์จากเว็บจริง) และ **graft** (แผนที่ของโค้ดคุณเอง) คีย์อยู่ใน `.env` ซึ่ง Claude อ่านไม่ได้ และไม่ไปโผล่ในบรรทัดคำสั่ง ตั้งต้นจะไม่เชื่อมอะไรเลย เพราะแต่ละ server เพิ่มรายการเครื่องมือของมันเข้าไปในทุกเทิร์น

</details>

<details>
<summary><b>ship เอง</b></summary>

<br>

ถ้าไม่เปิด Claude จะถามว่า "commit ไหม" แล้ว "push ไหม" แล้ว "เปิด pull request ไหม" และทุกคำตอบคือข้อความเพิ่มอีกหนึ่งข้อความ เลือกระดับครั้งเดียวด้วย `/easyclaude:autoship off`, `commit`, `push`, `pr` หรือ `merge` แล้ว Claude จะทำทุกขั้นจนถึงระดับนั้นเอง เมื่องานที่คุณขอเสร็จและการตรวจผ่านทั้งหมด มันยังถามเมื่อการตรวจไม่ผ่าน เมื่อการแก้แตะระบบล็อกอิน การจ่ายเงิน หรือ migration ของฐานข้อมูล หรือเมื่อคุณบอกให้รอ ปิดไว้ตั้งต้น ปิดในโฟลเดอร์ที่ไม่มี git และทุกเซสชันจะบอกระดับที่ตั้งไว้

</details>

## คำถาม

<details>
<summary><b>เปิดโปรเจกต์แล้วไม่มีอะไรเกิดขึ้น</b></summary>

<br>

เกือบแน่นอนว่ายังไม่มี Node.js easyClaude ทำงานบนตัวนี้ ถ้าไม่มี เซสชันจะเปิดเป็น Claude Code ธรรมดา ให้ติดตั้งรุ่น LTS จาก [nodejs.org](https://nodejs.org) เปิด Claude ใหม่ และพิมพ์ `/easyclaude:start` ถ้าการตั้งค่ายังไม่เริ่ม

</details>

<details>
<summary><b>ใช้กับโปรเจกต์ที่เริ่มไปแล้วได้ไหม</b></summary>

<br>

ได้ มันอ่านโค้ดที่มีอยู่ และถามเฉพาะสิ่งที่โค้ดบอกไม่ได้ มันเพิ่มเนื้อหาต่อจากบันทึกที่คุณมีอยู่แล้วโดยไม่เขียนทับ เช่น `CLAUDE.md` หรือ `AGENTS.md` ของคุณเอง ไฟล์สถาปัตยกรรม หรือโฟลเดอร์บันทึกการตัดสินใจ ถ้า `docs/` เป็นเว็บเอกสารที่เผยแพร่อยู่ มันจะเก็บบันทึกแผนงานไว้ใน `planning/` แทน เพื่อไม่ให้ไปโผล่บนเว็บ

ขั้นตอนตั้งค่าจะเขียนที่เก็บเหล่านี้ให้เอง ถ้าต้องการเปลี่ยนภายหลัง ให้แก้ไข `.claude/easyclaude.json` ส่วนไฟล์ที่ไม่ได้ระบุจะอยู่ที่เดิม:

```json
{ "files": { "state": "planning/STATE.md", "decisions": "doc/adr/" } }
```

ชื่อที่ใช้ได้คือ `state` (แผนงาน), `decisions`, `architecture`, `prd`, `changelog` และ `tokens` (ข้อกำหนดการออกแบบ) ทุกไฟล์ต้องเป็นไฟล์ Markdown ที่อยู่ในโปรเจกต์ ส่วน `decisions` ใช้เป็นโฟลเดอร์ที่ลงท้ายด้วย `/` ได้ด้วย แล้วการตัดสินใจแต่ละครั้งจะเป็นไฟล์ใหม่ที่มีเลขลำดับในโฟลเดอร์นั้น

</details>

<details>
<summary><b>มันรับประกันได้ไหมว่าโค้ดใช้ได้</b></summary>

<br>

ได้เท่าที่การตรวจของโปรเจกต์คุณครอบคลุม และมันจะบอกว่าคุณอยู่ในกรณีไหน เว็บไซต์ Python Go Rust และเครื่องมือบรรทัดคำสั่งตรวจได้ดี ส่วน Unity Unreal Android Studio และ iOS มักตรวจไม่ได้ถ้าไม่มีหน้าจอ จึงยืนยันได้แค่ว่าโค้ดคอมไพล์ผ่าน ไม่ใช่ว่าทำงานถูก

</details>

<details>
<summary><b>การตรวจจะขัง Claude ไว้ในวงวนไหม</b></summary>

<br>

ไม่ การตรวจที่ไม่ผ่านจะส่ง Claude กลับไปแก้ ตราบใดที่มันยังแก้ไฟล์อยู่ ถ้ามันไม่แก้อะไร เพราะสิ่งที่ต้องแก้ไม่ใช่งานของมัน เทิร์นจะจบและงานถูกบอกว่ายังไม่ได้ตรวจผ่าน การตรวจที่รันไม่ได้ เช่นไม่มีคอมไพเลอร์ จะแค่เตือน การตรวจที่ช้าตั้งเป็น `"tier": "full"` ใน `.claude/verify.json` ได้ ให้รันตอนงานเสร็จ ไม่ใช่ทุกเทิร์น การตรวจหน้าเว็บถามได้หนึ่งครั้งต่อข้อความ และปิดได้ด้วย `"look": false` ในโฟลเดอร์ที่มีหลายแอป ขั้นตอนตั้งค่าจะให้แต่ละแอปมีการตรวจของตัวเองด้วย `"dir"` และการแก้ไขจะรันเฉพาะการตรวจของแอปที่ถูกแก้ ถ้าแก้นอกทุกแอป จะรันการตรวจทั้งหมด

</details>

<summary><b>ถอนการติดตั้งอย่างไร</b></summary>

</details>

## ค่าใช้จ่าย

วัดด้วย Claude Code ในโปรเจกต์ที่ตั้งค่าแล้ว และแผนงานเป็นภาษาอังกฤษ

<!--measured:1710,934,27,265,484-->**ราว 1,710 โทเคนต่อเทิร์น**

| ส่วน | โทเคน | เริ่มเมื่อ |
|---|---|---|
| ทุกอย่างที่ปลั๊กอินโหลดตอนเริ่มเซสชัน | ราว 934 | ตั้งแต่ติดตั้ง |
| แผนงานใน `docs/STATE.md` ที่ข้อความเปิดอ่านกลับมา | ราว 27 | หลังตั้งค่า |
| `CLAUDE.md` ที่การตั้งค่าเขียน | ราว 265 | หลังตั้งค่า |
| กฎที่การตั้งค่าคัดลอกไปไว้ใน `.claude/rules/` | ราว 484 | หลังตั้งค่า |

ส่วนของแผนงานโตตามแผน และแผนภาษาไทยใช้โทเคนมากกว่าแผนเดียวกันในภาษาอังกฤษเล็กน้อย เนื้อสกิลและสูตรของแต่ละสแตกโหลดเฉพาะตอนที่ถูกใช้

มีสามจังหวะที่แพงกว่าปกติ และ easyClaude จะบอกคุณทุกครั้ง คือการเปิดบทสนทนาเก่า การเปลี่ยนโมเดลกลางบทสนทนายาว (มีบรรทัดบอกค่าใช้จ่ายเมื่อเกินราว $0.25) และบทสนทนาที่มีประวัติเกินราว 80,000 โทเคน ซึ่ง Claude จะแนะนำ `/clear` หนึ่งครั้ง และอีกครั้งหลังทุก `/clear` แผนของคุณอยู่ใน `docs/STATE.md` การ `/clear` จึงไม่ทำให้อะไรหาย

<details>
<summary><b>ค่าใช้จ่ายถูกคุมไว้อย่างไร</b></summary>

<br>

`node scripts/measure-cost.mjs` วัดตัวเลขด้านบน (ราว $1 ต่อครั้ง) และ CI จะไม่ผ่านถ้าหน้านี้อ้างตัวเลขอื่น CI ยังประมาณส่วนของปลั๊กอินเองทุกครั้งที่ push จากขนาดไฟล์ <!--cost:855,314,484,57-->**ราว 855 โทเคนต่อเทิร์น** แบ่งเป็นกฎราว 314 คำอธิบายสกิลราว 484 และคำอธิบายเอเจนต์ราว 57 `skills/registry.json` ตั้งเพดานไว้ที่ 1,400 และการ build จะไม่ผ่านถ้าเกิน

<!--always-on:8-->มีแปดสกิลที่โหลดอยู่ตลอด เพื่อให้ประโยคธรรมดาไปถึงมันได้ เจ็ดตัวคือขั้นตอนในตาราง "แค่บอกว่าอยากได้อะไร" รวมกับการตั้งค่า ตัวที่แปดคือ slopmonster ตัวตรวจข้อความ ราว 59 โทเคน อีกห้าสกิลที่ใช้นาน ๆ ครั้งโหลดเฉพาะเมื่อพิมพ์ จึงไม่มีค่าใช้จ่ายต่อเทิร์น เอเจนต์อ่านอย่างเดียวหนึ่งตัว คือผู้รีวิว diff ที่ `ship` ใช้ มีค่าใช้จ่ายราว 57 `.mcp.json` มาแบบว่างเปล่า เพราะรายการเครื่องมือของ MCP มักเป็นค่าใช้จ่ายที่ใหญ่ที่สุด และเพดานนี้นับมันไม่ได้

</details>

## สำหรับผู้ร่วมพัฒนา

```bash
node scripts/validate.mjs   # ตรวจโครงสร้างของปลั๊กอินและค่าใช้จ่ายที่อ้างไว้
node scripts/test.mjs       # ทดสอบตัวตรวจเอง โดยทำให้พังทีละอย่าง
node scripts/bench.mjs      # การวัดผลด้านบน (ต้องล็อกอิน และมีค่าใช้จ่าย)
```

[CONTRIBUTING.md](CONTRIBUTING.md) มีกติกาสำหรับการส่งการแก้ไข และ [SECURITY.md](SECURITY.md) บอกวิธีแจ้งปัญหาด้านความปลอดภัยแบบส่วนตัว ไม่มี dependency ใช้แค่ของที่มากับ Node ใน [`evals/README.md`](evals/README.md) มีการวัดผลและกรณีทดสอบการเลือกสกิล [ROADMAP.md](ROADMAP.md) บอกว่าจะทำอะไรต่อและเพราะอะไร [`recipes/`](recipes/) มีการตรวจสำหรับสิบสแตก ตั้งแต่ Go ถึง Unity
